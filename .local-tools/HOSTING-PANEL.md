# Развёртывание на хостинге с панелью

Репозиторий содержит тему и публичный контент. WordPress, ACF, пароли, заявки и локальная база в Git не хранятся.

## Перенос текущей установки целиком

1. Сделайте резервную копию локального сайта и базы `strojka_local`.
2. В панели добавьте домен, выпустите SSL и создайте отдельную базу и пользователя базы. Используйте актуальную поддерживаемую версию PHP, совместимую с установленным WordPress и ACF.
3. Перенесите установку инструментом миграции WordPress либо вручную. При ручном переносе нужны файлы ядра WordPress, активный ACF, тема `wp-content/themes/strojka`, содержимое `wp-content/uploads` и экспорт базы через phpMyAdmin. Экспорт базы содержит пользователей и заявки: передавайте его приватно, не кладите в Git и удалите из публичной папки после импорта.
4. В новом `wp-config.php` укажите данные базы хостинга, новые ключи безопасности и отключите вывод отладочных ошибок. Не используйте локальные учётные данные.
5. Инструментом миграции с поддержкой сериализованных данных замените `http://127.0.0.1:8085` на рабочий HTTPS-домен. Не делайте обычную текстовую замену в SQL. Если есть WP-CLI, начните с `wp search-replace 'http://127.0.0.1:8085' 'https://ВАШ-ДОМЕН' --all-tables-with-prefix --skip-columns=guid --dry-run`, проверьте результат и только затем повторите без `--dry-run`.
6. В WordPress откройте «Настройки → Постоянные ссылки» и сохраните структуру «Название записи». На Apache проверьте `.htaccess`; на Nginx попросите поддержку настроить передачу несуществующих путей в `index.php`.
7. Проверьте главную, `/vakansii/`, страницы `/uslugi/.../`, изображения, Яндекс Карты и все формы. Заявки должны появляться в админке.
8. Настройте почтовую доставку и проверку её результата отдельно. Сейчас формы сохраняют заявки в базе, уведомления по почте не подключены.
9. Выполните проверки из [SEO-LAUNCH.md](SEO-LAUNCH.md), затем откройте индексацию и отправьте sitemap в поисковые кабинеты.

Не загружайте в публичную папку `.git`, `.local-tools`, `local-access.txt`, `wp-cli.phar`, архивы, SQL-дампы, логи, тесты и локальные скрипты запуска.

## Чистая установка из Git

1. Установите русский WordPress средствами панели и бесплатный Advanced Custom Fields через админку.
2. Загрузите папку `wp-content/themes/strojka` из репозитория в одноимённую папку сайта и активируйте тему.
3. Если в панели доступен терминал с WP-CLI, временно разместите `setup-project.php` и `project-content.json` из `.local-tools` в закрытой служебной папке. Из корня WordPress выполните `wp eval-file /ПОЛНЫЙ/ПУТЬ/setup-project.php`. Оба файла должны находиться рядом. Скрипт восстановит публичные страницы, услуги, показатели, меню и демонстрационные фото. После успешного восстановления удалите служебную копию файлов с хостинга.
4. Если терминала нет, используйте перенос текущей установки целиком либо попросите поддержку выполнить импорт. Простая загрузка темы не переносит данные из базы.
5. Настройте реальные контакты и ссылки Telegram/MAX, проверьте формы, постоянные ссылки и SEO перед открытием индексации.

Не заменяйте существующий `.htaccess` панели целиком: сохраните правила SSL, кеширования и безопасности хостинга, согласовав добавление правил WordPress.
